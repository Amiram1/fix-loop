# Vikunja codebase brief

Vikunja is a self-hosted to-do app. The Go API lives in `pkg/`. The Vue 3 + TypeScript frontend is in `frontend/`. `veans/` is a separate Go module with its own `veans/AGENTS.md`. Contributor rules are in `AGENTS.md` (`CLAUDE.md` is a symlink to it) and `.agents/docs/*.md`.

## 1. Stack

- **Backend:** Go (`go 1.27.0` in `go.mod`, module `code.vikunja.io/api`).
  - HTTP: Echo v5 (`labstack/echo/v5`) for v1 and the router, and Huma v2 (`danielgtaylor/huma/v2`) for `/api/v2`.
  - ORM: XORM v1.4.1 (`xorm.io/xorm`).
  - Databases: SQLite (go-sqlite3), MySQL/MariaDB and Postgres (pgx). ParadeDB is used for full-text search when installed (`pkg/db/db.go`).
  - Other libraries: cobra (CLI), watermill (events), go-redis, JWT, go-oidc, go-ldap, an MCP SDK, Sentry, an S3 SDK.
  - Build tool: mage (`magefile.go`).
- **Frontend:** Vue 3.5, Vite 8, Pinia, vue-router 5, TanStack Vue Query 5, TipTap editor. TypeScript 6, Vitest 4 and Playwright (e2e). pnpm 11, Node >=24 (`frontend/package.json`).
  - API client generated by `@hey-api/openapi-ts` (`frontend/openapi-ts.config.ts`).
- **Other:** `desktop/` (desktop wrapper), `veans/` (CLI Go module), Docker, `nfpm.yaml` packaging, devenv/mise configs.

## 2. Build, run and test

Go tasks go through **mage**. List targets with `mage -l`. Plain `go test` does not work (`AGENTS.md`). The mage tests call `ensureFrontendDistExists`. CI creates a stub with `mkdir -p frontend/dist && touch frontend/dist/index.html`. `frontend/embed.go` presumably embeds `frontend/dist`.

| Purpose | Command | Source |
|---|---|---|
| Build API binary | `mage build` | `magefile.go` `Build.Build`; CI runs `./mage-static build` |
| Feature (unit) tests | `mage test:feature` | Runs `go test -p 1 -short ./...` with a coverprofile |
| Web tests | `mage test:web` | Runs `./pkg/webtests`, without `-short` |
| Single Go test | `mage test:filter <go-test-run-regex>` | Runs all packages with `-short`, then reruns `pkg/webtests` without it |
| CalDAV tests | `mage test:caldav` | `pkg/caldavtests` |
| API e2e tests | `mage test:e2e-api` | `pkg/e2etests`, real event pipeline |
| Playwright e2e | `mage test:e2e "tests/e2e/misc/menu.spec.ts"` | Starts its own API with an in-memory DB and the dev server. Never run `pnpm test:e2e` directly. |
| Backend lint | `mage lint:fix` | Config in `.golangci.yml` |
| Regenerate frontend client | `mage generate:frontend-client` | Verify with `mage check:frontend-client` |
| Regenerate config sample | `mage generate:config-yaml` | Output is `config.yml.sample`, generated from `config-raw.json` |
| Check translations | `mage check:translations` | Run in CI |
| New migration scaffold | `mage dev:make-migration <StructName>` | Also `dev:make-event`, `dev:make-listener`, `dev:make-notification` |

- **Save test output:** `mage test:filter Foo 2>&1 | tee /tmp/out.log`, then read the log. Tests are slow, so don't rerun just to grep.
- **Test DB:** the default is an in-memory SQLite. To use a real DB, set `VIKUNJA_TESTS_USE_CONFIG=1` plus `VIKUNJA_DATABASE_TYPE`, `_USER`, `_PASSWORD`, `_DATABASE`, `_HOST` and `_SSLMODE` (the env block in `.github/workflows/test.yml`).
- **Other test env:** CI sets `VIKUNJA_SERVICE_PUBLICURL=http://127.0.0.1:3456` and LDAP variables (`VIKUNJA_AUTH_LDAP_*`) against an OpenLDAP container. S3 tests need MinIO (`VIKUNJA_FILES_TYPE=s3`).
- **Fixtures:** `pkg/db/fixtures/`.
- **CI matrix:** feature and web tests run on sqlite-in-memory, sqlite, postgres, mariadb, mysql and paradedb. There is also a migration smoke test, which runs `vikunja migrate` from the unstable release and then from the new build.
- **Frontend**, run in `frontend/`:
  - `pnpm dev` (port 4173) and `pnpm build`.
  - `pnpm lint` / `pnpm lint:fix`, and `pnpm lint:styles` / `pnpm lint:styles:fix`.
  - `pnpm test:unit` (vitest). Single file: `pnpm vitest run <file>`.
  - `pnpm typecheck` (`vue-tsc --build --force`). It has more than 1000 pre-existing errors, so diff the normalized error set against the base branch (recipe in `.agents/docs/testing.md`).
- **`.fixloop.yml`:** a demo config that runs `go test ./pkg/utils/ -run {{name}}` and `pnpm vitest run {{file}}`. `AGENTS.md` says plain `go test` doesn't work, so prefer mage.
- **Running the server:** the `web` cobra command in `pkg/cmd/web.go`. Other commands: `migrate`, `dump`, `restore`, `repair*`, `doctor`, `user`, `testmail`, `healthcheck`. Config comes from a config file, and environment variables override it (`VIKUNJA_<SECTION>_<KEY>`).

## 3. Directory map

- `main.go`: entry point, calls into `pkg/cmd`.
- `pkg/`: all backend code.
  - `cmd/`: cobra commands.
  - `config/`: config keys and defaults.
  - `db/`: XORM engine and sessions; `db/fixtures/` holds test fixtures.
  - `models/`: domain models, CRUD, permissions (`Can*`), events, listeners, cron jobs.
  - `user/`: user model, tokens, TOTP, password reset.
  - `web/`: `web.go` holds the `Auth`/`CRUDable` interfaces. `web/handler/` holds the `Do*` pipeline (`core.go`, `create.go`, `read_one.go`, `read_all.go`, `update.go`, `delete.go`).
  - `routes/`: `routes.go` registers everything. `api/v1/` is Echo and frozen. `api/v2/` is Huma, one file per resource, with `registry.go`, `huma.go` and `errors.go`. `api/shared/`, `caldav/`, `feeds/`, `middleware/`, plus `rate_limit.go`, `static.go` and `error_handler.go`.
  - `modules/`: `auth/` (JWT, `ldap/`, `openid/`, `oauth2server/`), `humabridge/`, `mcp/`, `migration/` (importers such as Trello, TickTick, Wekan and CSV), `avatar/`, `background/`, `dump/`, `keyvalue/`.
  - `migration/`: schema migrations, one timestamp-named file each (e.g. `20260928140648.go`), with `migration.go` and `schema_check.go`.
  - `events/`, `notifications/`, `mail/`, `cron/`, `websocket/`, `files/`, `audit/`, `license/`, `plugins/` (with `yaegi_symbols/`), `richtext/`, `i18n/`, `metrics/`, `log/`, `utils/`, `swagger/` (generated, don't edit).
  - Test packages: `webtests/` (HTTP integration, `huma_*_test.go` for v2), `caldavtests/`, `e2etests/`.
- `frontend/src/`:
  - `client/`: generated SDK in `generated/`, `queries/` (TanStack modules), `http.ts`, `queryClient.ts`, `problem.ts`, `requestContext.ts`.
  - `components/`, `views/`, `composables/`, `stores/` (Pinia), `router/`, `helpers/`, `i18n/`, `modules/`, `styles/`, `sw.ts`.
  - `frontend/tests/e2e/` holds Playwright specs. `frontend/tests/` also has `factories/`, `fixtures/` and `support/`.
- `veans/`: separate module with its own mage/lint/test CI jobs.
- `desktop/`, `contrib/`, `examples/`, `build/`, `scripts/`, `rest/`, `.agents/` (docs and skills), `.github/` (workflows).

## 4. Key modules and request flow

**Request flow (CRUD):**
1. A route in `pkg/routes/routes.go` goes to either a v1 Echo handler (`pkg/routes/api/v1/`) or a v2 Huma operation (`pkg/routes/api/v2/<resource>.go`, registered via `Register(api, huma.Operation{...}, fn)`).
2. Both call the `Do*` functions in `pkg/web/handler/` (`DoCreate`, `DoReadOne` and so on). These are framework-agnostic.
3. Each `Do*` function opens a `db.NewSession()` (or a read session), calls the model's `CanCreate`/`CanRead`/`CanWrite`/`CanDelete`, then the model method (`Create`, `ReadOne`, `ReadAll`, `Update`, `Delete`). It rolls back on error, commits, and dispatches pending events (`events.DispatchPending`).
4. Models in `pkg/models/` use XORM (no raw SQL allowed). Permissions live in `*_permissions.go` files and are shared by v1 and v2.
5. Events go over watermill to listeners in `pkg/models/listeners.go`. A listener only fires if registered with `events.RegisterListener`.

**Non-CRUD v2 actions** have no `Do*` wrapper. The handler must load the entity and call `Can*` itself (`.agents/docs/api.md`).

**Auth:**
- `pkg/routes/routes.go` has an unauthenticated path set for v1 and v2.
- `pkg/modules/auth/` handles JWT, sessions (`pkg/models/sessions.go`), API tokens (`pkg/models/api_tokens.go`, `pkg/routes/api_tokens.go`), link shares (`pkg/models/link_sharing.go`) and OIDC, LDAP and OAuth2.
- Admin v2 routes are gated by `gateV2AdminRoutes` (`pkg/routes/routes.go`, `admin_gate.go`).

**Tasks (largest area):**
- `pkg/models/tasks.go` holds the Task model, repeat logic and `updateDone`.
- `task_collection.go`, `task_collection_filter.go` (fexpr filter parsing) and `task_collection_sort.go` handle listing and filtering.
- `task_search.go` covers search, `task_position.go` positions, `kanban.go` buckets, and `project_view.go` views.
- `task_reminder.go` and `task_overdue_reminder.go` cover reminders.
- Other related files: `task_relation.go`, `task_assignees.go`, `task_comments.go`, `task_attachment.go`, `time_tracking.go`, and `favorites.go`.

**Projects and sharing:** `project.go`, `project_permissions.go`, `project_users.go`, `project_team.go`, `teams.go`, `saved_filters.go` and `link_sharing.go`. Pseudo-projects are Favorites (id -1) and saved filters (negative ids).

**MCP:** `pkg/modules/mcp/`. New v2 operations are exposed only if added to the allow-list in `pkg/modules/mcp/exposure.go`.

**Frontend flow:** component → composable (`composables/useX.ts`, read side) or mutation hook (`client/queries/x.ts`) → generated SDK (`client/generated`) → shared client (`client/http.ts`, which handles the bearer token and a single refresh-and-retry on 401 code 11).
- The reference implementation is `client/queries/projects.ts` plus `composables/useProjects.ts`.
- The API base URL comes from `frontend/src/helpers/apiUrl.ts` (`getApiBaseUrl()`), never from `window.API_URL` directly.
- `pkg/routes/static.go` injects `service.publicurl` into `index.html`.

## 5. Conventions

- **API versions:** every new route goes on `/api/v2`. `/api/v1` is frozen (bug fixes and ports only).
  - v2 verbs: POST creates, PUT/PATCH update (v1 is the reverse).
  - URLs are kebab-case and JSON is snake_case.
  - v2 OpenAPI is generated from Go types. v1 uses swaggo annotations.
- **Generated files:** never hand-edit `pkg/swagger/`, `config.yml.sample` or `frontend/src/client/generated`.
- **Skills** (in `.claude`/`.agents`) to invoke before touching these areas: `crudable` (models), `migration` (`pkg/migration/`), `api-v2-routes`, `run-e2e-tests`.
- **Go style:**
  - Multi-field struct literals and multi-entry slice or map literals go one entry per line with trailing commas.
  - Wrap errors with `fmt.Errorf("...: %w", err)`.
  - No raw SQL anywhere (migrations and tests too). Use the XORM builder.
  - An argument-less `builder.In("col")` is dropped by `Where` and matches every row. Pass a typed empty slice.
  - Random tokens use `utils.Sha256Hex`. Passwords use bcrypt.
  - Never log secrets.
  - Comments explain *why* only.
  - Files carry the AGPL header (`code-header-template.txt`).
- **Errors:** domain errors are typed (`pkg/models/error.go`, `pkg/user/error.go`) with `HTTPError()`. v2 maps them in `pkg/routes/api/v2/errors.go` (`translateDomainError`).
- **Go tests:** `*_test.go` sit next to the code. Every permission path needs a positive and a negative test. Use fixtures instead of inventing data. A regression test must fail on the unfixed code.
- **Frontend style:**
  - Same one-entry-per-line literal rule, with lines under ~120 columns.
  - Importing `axios` or any `models`, `modelTypes` or `services` path is an ESLint error.
  - Cache writes happen only in mutation option callbacks.
  - Mutations use `contextMutationOptions`. Secrets go through `useSecretMutation`.
  - Don't mutate a parent's `v-model` in place. Use `aria-disabled` instead of native `disabled` on focusable controls.
- **Frontend tests:** prefer Playwright e2e that asserts stored state after a reload. Use component tests only for race and timing cases. Mock `@/client/generated` with `vi.mock`. Drag-position fixtures should be asymmetric (100/250/300).
- **Commits:** Conventional Commits (`cliff.toml` generates the changelog).

## 6. Likely bug areas

- **Task repeat and date math** (`pkg/models/tasks.go`).
  - Three modes: `setTaskDatesDefault`, `setTaskDatesMonthRepeat` and `setTaskDatesFromCurrentDateRepeat`.
  - `addRepeatIntervalToTime` has overflow and DoS guards (GHSA-r4fg-73rc-hhh7). `setTaskDatesDefault` and `setTaskDatesMonthRepeat` assign `newTask.Reminders = oldTask.Reminders` and then mutate the elements, so they share and alias the slice.
  - Time zones and zero dates also matter here (`pkg/utils/time.go`, `clampDateToDriverRange` in `task_collection_filter.go`).
- **Task filters and sorting** (`pkg/models/task_collection_filter.go`, `task_collection_sort.go`, `task_search.go`).
  - Filter strings are preprocessed (operator replacement, quoted runs), parsed by fexpr, and checked by `validateFilterComplexity`.
  - Date-math and `filter_timezone` handling can go wrong.
  - Search behaves differently across DB drivers (ParadeDB, Postgres, MySQL, SQLite), and behavior can differ per database.
- **Permissions and authorization** (`pkg/models/*_permissions.go`, `project_access*.go`).
  - Hierarchy via sub-projects and pseudo-projects, multiple teams, link shares, archived projects, API-token scopes (`api_tokens_permissions.go`, `pkg/routes/api_tokens.go`).
  - IDOR checks on attachments and relations (`pkg/webtests/task_attachment_idor_test.go`, `task_relation_authz_test.go`).
  - Admin bypass (`admin_bypass.go`).
  - Non-CRUD v2 handlers must call `Can*` themselves, so they are easy to miss.
- **Pagination and sorting:** the server silently caps `per_page` at `max_items_per_page`. The frontend must drive paging from `total_pages` (`fetchAllPages`). Kanban buckets paginate per bucket, and refetching collapses scrolled buckets (`pkg/models/kanban.go`).
- **Positions** (`task_position.go`, `pkg/cmd/repair_task_positions.go`). Positions are computed as midpoints, which can collide or run out of precision, hence the repair commands.
- **Migrations** (`pkg/migration/`).
  - Must work on sqlite, mysql, mariadb and postgres. Raw SQL is forbidden.
  - New files need a unique timestamp ID. Check `schema_check.go` and the smoke-test CI job.
- **XORM quirks:** an empty `builder.In` matches everything. Struct zero-value updates need `.Cols(...)`. Sessions must be rolled back and events cleaned up on error (see `pkg/web/handler/core.go`).
- **Events and listeners:** an unregistered listener silently does nothing. Events dispatch only after commit.
- **Frontend cache state** (`frontend/src/client/queries/*`).
  - Stale or optimistic cache writes, and paged lists whose `total` and `total_pages` must be rewritten on every cached page.
  - Invalidation must happen in `onSettled`.
  - Pseudo-project ids (negative) have no detail endpoint.
  - Request-context changes mid-request (`isRequestContextAbort`).
  - A `mutateAsync` rejection that escapes can toast twice.
  - A draft composable whose state goes stale when mutations update the list.
- **Frontend auth and API URL:** token refresh failure kinds (`RefreshTokenError`), the 304 AutoPatch response on a no-op settings PATCH, and `setSession()` clearing the cache on an identity change.
- **Rate limits, SSRF, uploads:** `pkg/routes/rate_limit.go`, `code.dny.dev/ssrf` (used for webhooks and HTTP clients, `pkg/utils/httpclient.go`), and avatar or attachment upload handling.
- **License gating:** `pkg/license/` and `pkg/routes/feature_gate.go`. Ask before removing or bypassing license checks (`AGENTS.md`).
